# Lyrico 1.6.1（Windows x64 桌面版）

Lyrico 的 **Windows 原生桌面版**：从原 Android 版完整移植到 Kotlin/JVM + Compose Multiplatform，界面上仍是熟悉的 Miuix 风格，数据格式与安卓版同源（同一套 Room 结构与偏好键）。适用于本地音乐库的标签编辑、歌词处理、封面管理与批量任务。

## 下载哪个

| 文件 | 大小 | 说明 |
|---|---|---|
| `Lyrico-1.6.1.msi` | 140.2 MiB | **推荐**。Windows 安装包，**自带运行时**，不需要机器上装 Java；带开始菜单与快捷方式，可选安装目录 |
| `Lyrico-1.6.1-windows-x64-portable.zip` | 115.0 MiB | 便携版：解压后双击 `Lyrico.bat`。**需要机器上有 Java 21+**（`JAVA_HOME` 或 `PATH`），数据放在解压目录下的 `data/`，整体可搬走/备份 |

应用数据目录默认**便携优先**：程序目录可写时用 `<程序目录>\data`，不可写（例如装在 `Program Files`）时回退到 `%LOCALAPPDATA%\Lyrico`；也可用 `-Dlyrico.data.dir=<路径>` 显式指定。

## 本版要点

**桌面交互补齐**（v1.6.0 的审计里列为 P1/P3/P4 的那几条）：

- **右键菜单**：歌曲行右键弹出菜单（播放 / 重命名文件 / 删除歌曲），列表页通用。
- **多选**：Ctrl+点击增减单行、Shift+点击选范围（锚点跟随最后一次点击，与资源管理器一致）、长按拖动仍然可用。
- **键盘**：`Esc` 退出多选；**`Esc` 先交给前台浮层**（打开着的 sheet / 对话框关掉，而不是退多选）；`Ctrl+A` 全选当前列表可见的曲目。
- **窗口几何持久化**：位置与大小在关闭时写入 `data/window.json`，下次启动原样恢复；另有最小尺寸下限，避免拖成几个像素。
- **单实例锁**：同一数据目录只允许一个实例，第二次启动会弹对话框说明并退出（不同数据目录的两个安装互不影响）。

**同时修掉一个验收工具自身的 bug**（它曾让「证据」失真，如实记录）：取证脚本 `scripts/send-keys.ps1` 里 Win32 `INPUT` 结构的联合体只声明了一个成员，尺寸因此是 32 字节而不是 40，`SendInput` 会**返回 0 并置 `ERROR_INVALID_PARAMETER` 而不抛异常** —— 旧脚本没检查返回值。修好后重测，并发现上一轮留下的一张证据图（`c9-03-esc-closes-menu.png`）与「菜单还开着」的那张**逐像素相同**，即它记录的其实是失败；已用重拍的帧替换（同一对照差异 65.7%）。上一版发布说明里若有与之相关的说法，以本版为准。

## 第三方组件与许可

与 1.6.0 相同，未新增或移除依赖。应用内「关于 → 开源许可」列出全部组件；`THIRD_PARTY_NOTICES.md` 与包内 `LICENSE.txt` 为随包声明。要点：

- **FFmpeg（LGPL v3）**：`ffmpeg/windows-x64/ffmpeg.exe` 是 BtbN/FFmpeg-Builds 的**未修改** LGPL 构建，作为**独立进程**（边车）调用，许可证文本随二进制一起分发（同目录 `LICENSE.txt`）。它只用于响度分析；缺少它时应用仍可正常使用，仅该功能不可用。固定版本与哈希见仓库 `docs/third-party/ffmpeg-lgpl.md`。
- **TagLib**（LGPL-2.1 或 MPL-1.1）、**libebur128**（MIT）、**quickjs-ng**（MIT）：静态/动态链接见上述清单，含许可证文本位置。
- 其余依赖（Compose Multiplatform、Miuix、Koin、Room、OkHttp、Coil 等）均为 Apache-2.0，版本号由构建期从 `gradle/libs.versions.toml` 生成。

## 已知限制（如实列出）

1. 桌面端没有系统「返回手势」，各页用自带的返回/关闭控件（`Esc` 现在能关前台浮层，但不能替代页内返回按钮）。
2. **`Ctrl+A` 没有真窗口证据**：本机的键盘注入有两条硬限制 —— `SendInput` 的虚拟键会被 Windows 的文本输入通道（TSF/IME）吃掉、进不到窗口；`PostMessage` 能把普通键送进窗口（`Esc` 的证据就是这么拍的），但修饰键状态送不进去，`Ctrl+A` 到达时被当作普通 `A`。该行为由无头测试覆盖（驱动真实 `KeyEvent`，5 项），未在真窗口复核。
3. 「用其它程序打开」只走系统默认关联程序；安卓那种「指定播放器包名/选择器」没有等价物。
4. 液态玻璃悬浮栏的视觉效果未移植（毛玻璃与纯色保留）。
5. 主题键色：默认项不跟随壁纸取色；薄荷模式下键色不生效。
6. 命令行传入的文件暂未接到编辑页（双击关联文件只会打开曲库首页）。
7. 部分英文文案的复数形式未处理（如 `1 folders found`）。
8. 开源许可清单为手工维护 + 构建期生成的混合，若上游依赖新增而清单未同步，页面可能滞后。
9. 长列表的滚动条可见性只有代码层结论（未做真窗口像素级复核）。

完整记录（含每条缺口的出处、测试口径与真窗口证据索引）见仓库 `PLAN.md` 的 P5/P6 各节（本版对应 §6h）。
